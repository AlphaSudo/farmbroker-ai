## Release package

- `release-manifest.json`: commit/tag, migration versions, regions/tier, model/prompt versions, timestamps; no secrets.
- `functional-results.json`: actual pass/fail/blocked per required scenario, correlated provider/run IDs.
- `performance-results/`: seeds, workload scripts, raw histograms, SQL plans, browser traces, comparisons.
- `decision-evidence.json`: redacted specification/evidence/candidate/selection/commit hashes.
- `impact-notes.md`: audience hypothesis, consent, observed results, sample/proxy labels, assumptions.
- `capability-table.md`: actual API interactions, simulated operations, future integrations.
- Demo script/video links mapped to the release.

Public evidence is redacted. Give judges scoped sandbox/testing access through appropriate instructions; do not publish provider/service-role/model keys or unrestricted operator credentials.

## Demonstration spine

1. A bulk buyer describes the order and confirms normalized constraints.
2. AI selects a meaningful feasible plan and the accepted quote binds it.
3. Actual capture unlocks atomic execution.
4. Hub rejects 2T; accepted 8T stays fixed; AI repairs the gap under the same charge.
5. Replacement passes inspection, settlement is calculated, simulated handover completes.
6. A clearly labeled separate order demonstrates actual refund.
7. One measured architecture result and one audience observation support the close.

Show architecture through a concise evidence panel/diagram. Accelerated provider waits need a visible label. Never edit different order IDs or simulated provider results into a claimed continuous successful transaction.
